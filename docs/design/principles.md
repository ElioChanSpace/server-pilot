# UI / 交互设计原则

本文件记录 server-pilot 的界面设计原则与决策，借鉴自 [ftop](https://github.com/Nongfsq/ftop)
的 `docs/product` 决策记录方式。新增或修改视觉/交互前先读本文；**拒绝清单**中的条目不要再引入。

## 借鉴来源

ftop（MIT）的界面决策文档给了可迁移的原则，而不是可照搬的界面。server-pilot 是
SSH 运维工具（多窗口、终端、大量列表与 Modal），不是常驻监控面板，因此取其原则、
弃其极端做法（如"几乎无文字"）。

## 原则

### 1. 视觉语言：徽章 + 数字

- 每个数值由一枚固定尺寸的圆形徽章（`--badge-size`）引入，徽章内是 10px 图标。
- 是"份额"的数值在徽章外圈加弧（`MetricBadge` 的 arc），弧长即数值。
- 颜色说明归属：CPU / 内存 / 磁盘 / 网络 / GPU 各有语义色，不靠文字标签重复说明。
- 一行内数值用同一字号。单位比数字小一号且用弱化色。

### 2. 数字排版

- 数值一律 `font-variant-numeric: tabular-nums`。
- 小数规则：小于 10 显示一位小数，10 及以上取整（`0.4` / `9.9` / `10` / `100`）。
- 硬件/远端读不到的数值显示 `—`，**绝不显示 0**（0 是有效读数）。

### 3. 列表要"静"（a list that rests）

- 实时刷新的排名列表（进程、容器）用"水平值"排名：读数升高立即上升，回落约 4s 慢衰减。
- 相差不超过阈值（CPU 差 `12%+1pt`、内存差 `4%+24MB`）不换位，避免两条互咬。
- 行的移动方式按距离分：与相邻行交换则滑过（spring ~330ms）；跨多行则原地翻页
  （淡出上移 140ms → 新位淡入 220ms），绝不横穿列表。一批移动 ≤400ms。
- 指针悬停在列表上时锁定顺序，点得到要点的行。

### 4. 详情浮卡，不是弹窗

- 点击列表行弹出详情卡（独立浮层，不改变面板尺寸），从行位置生长。
- 再点 / Esc / 点别处 / 窗口失焦即消失。卡片开启期间不再有其它悬停反馈。
- 行按压有反馈（缩小 0.97 + 高亮，回弹）。

### 5. 动效克制

- 数值、弧、进度条用约 300ms `ease-out` 追新读数，不做常驻动画。
- 布局切换交叉淡入。
- 一律尊重 `prefers-reduced-motion`（`useReducedMotion`），降级为纯淡入或直接切换。
- 明确拒绝 ftop 那种 0.65s 延迟、动画器常驻的连续缓动：运维工具的读数要"跟手"。

### 6. 一个表面的玻璃

- 全应用共用一套玻璃令牌（`--glass-bg` / `--glass-border` / `--glass-blur` /
  `--overlay-bg` / `--overlay-blur`），不各自写 rgba。
- 模块之间用间距和背景层级区分，不画分割线。
- 例外：密集数据表的行分隔线保留（运维表格需要扫读锚点），但监控面板与
  设置面等"模块堆叠"的表面不画分割线。
- 圆角、控件高度、焦点环走设计令牌。

### 7. 安静

- 窗口隐藏或最小化到托盘时暂停所有轮询（监控、状态、Modal 轮询），恢复时立即补一次采样。
- 不可见就不读数，不空转。

### 8. 设置即改即生效

- 设置是一块控制面：常用项是圆形开关，低频数值收进"更多"就地展开。
- 改动立刻生效并持久化，不需要"保存"按钮。

### 9. 图标（菜单栏/托盘）

参考 Thor（自绘 template PNG）与 Leap（SF Symbol）的做法：**单色剪影 + template 渲染**。

- 图形：双层机架（服务器集群语义），实心剪影 + 负空间细节；每单元 =
  左侧单状态点 + 右侧三条散热槽（服务器面板图标惯例）。
- 18px 可读：细节最小边 ≥ 1.5px。预览对比过"双点"版——18px 下两点糊成
  一团且显脸谱感，故取单点。
- 渲染：macOS 用白色版 + `icon_as_template(true)`（纯白/纯黑随菜单栏
  自适应）；Windows/Linux 用深色版（浅色任务栏可读）。
- 单一设计源 `design/tray-icon.svg`，`npm run gen:tray-icon` 栅格化出
  `src-tauri/icons/tray-template.png` / `tray-dark.png`（产物入库，构建
  不依赖脚本）。
- 应用/Dock 图标（`icons/icon.png`）不受此规则约束，另行设计。

## 落地记录（实现时的决策）

- **终端配色**（调研 iTerm2/Tabby/WindTerm/Warp/PuTTY 等后采纳）：
  - SSH 进程显式声明 `TERM=xterm-256color` + `COLORTERM=truecolor` 并
    `SendEnv=COLORTERM`——GUI 进程没有 TERM 时远端 dircolors/ls/git 与默认
    彩色提示符会全部退化为无色，这是"终端内容没有配色"的根因。
  - `drawBoldTextInBrightColors`（加粗走亮色档）、`minimumContrastRatio: 4.5`
    （WCAG AA 保底，VS Code 同值）、`cursorInactiveStyle: outline`。
  - 字体栈 JetBrains Mono / Cascadia Mono / SF Mono / Menlo；终端四周留白、
    细圆角滚动条；URL/路径可点击（web-links）。
  - 远端侧职责（不在客户端硬造）：`ls --color`/`LS_COLORS`/提示符 PS1/24bit
    声明；客户端保证的是能力声明与渲染质量。

- **条带形态**：底栏（BottomBar）这类窄条带用「图标 + 数字 + 弱化单位」，
  不放大徽章（ftop 的 strip 同理）；面板/卡片内的指标用完整徽章（`MetricBadge`）。
- **进程列表**：`ProcessManagerModal` 仅在实时读数列（CPU/内存）降序时用稳定排序
  （`useSteadyRanking`）；用户点其它列排序是明确意图，普通排序即可。
- **Docker 列表**：无逐秒变化的读数，不适用稳定排序，未改。
- **窗口**：编辑器窗口为无边框窗口——加了工具栏拖拽区（此前无法拖动窗口）、
  置顶/隐藏按钮、任意边缩放手柄（`WindowResizeHandles`）；主窗口有原生边框缩放。
- **主题**：新增三套参考 ftop 调色板的主题——「深海」（sea：性能核蓝/能效核青，
  墨蓝玻璃深色）、「暖白」（warm：暖白 + 琥珀，标志色）、「石墨」（graphite：
  冷白 + 石墨强调，浅色终端与其它浅色主题一致）。内置主题 ID 见
  `BUILTIN_THEME_IDS`。
- **安静轮询**：统一走 `usePolling`（监控面板、进程、连接、日志、指标历史、
  应用状态）；隐藏/最小化暂停，恢复可见立即补一次采样。被其它窗口完全遮挡
  的检测各平台不一，未做。
- **动画实现**：列表 FLIP / 详情卡生长 / 开关反馈用 framer-motion；数值缓动、
  弧与进度条过渡用 CSS/rAF（`useAnimatedNumber`）。全部尊重
  `prefers-reduced-motion`。

## 拒绝清单（do not reintroduce）

以下做法已被评估并否决，不要在后续改动中重新引入：

- 模块之间的分割线（divider lines）。
- 一行/一块内混用不同尺寸的徽章。
- 数值前的文字标签堆砌（能用徽章颜色和图标说明的不再写"CPU使用率："）。
- 常驻连续缓动动画（柱子/弧 0.65s 追值、渲染器持续动画）。
- 读不到的数据显示 0。
- 列表行大距离换位时横穿列表飞过去。
- 点击行在原地展开详情（改变行高导致列表抖动）。
